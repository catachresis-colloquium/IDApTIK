IDApTIK launch flow

Follow the ticks. A red cross stops the flow. Never tell the joiner to start until the host displays the green readiness message.

Host

1. Runtime diagnosis
Machine, OS/kernel, WSLg transport, graphics, audio, Rust, Elixir, network route and Tailscale are checked before anything launches.
If WSLg enters [WARN: COPY MODE]
The launcher uses a native Windows Bevy client when Windows interop and its cross-build tools are available. The relay and Tailscale route remain in WSL. If fallback prerequisites fail, in Windows PowerShell as Administrator run:
wsl --update
wsl --shutdown
Reopen Debian. Restart Windows if it remains.
2. Build
Wait for ✓ Bevy GUI build is complete. Cargo may take several minutes on the first machine. Do not invite anyone while it says building.
3. Relay and route
The Phoenix/Bandit relay must answer on port 4000. Under WSL2 NAT, Tailscale must be installed, running and authenticated.
● READY FOR JOINERS
Only now share the displayed tailnet address.

Joiner

1. Wait for the host
The host must explicitly say that their screen shows READY FOR JOINERS.
2. Runtime diagnosis and local build
The same machine/display/dependency checks run locally. Wait until the joiner's GUI build has a tick.
3. Exact relay probe
The launcher tests the supplied host and port. An unreachable relay is a cross, not a half-started game.
● READY — JOINING HOST NOW
The client starts only after all gates pass.

Friendly fault map

Penguin icon; WSLg window will not open
The launcher should select the Windows-native client. If it reports missing Windows target/linker/interop prerequisites, repair those or use the Windows update/shutdown recovery above.
WSLg window opens, then dies immediately
That early exit is surface/present-mode negotiation, not a game bug. Run ./launcher.sh --solo --windows-client to bypass WSLg with the native Windows client; provision it once with just windows-client-deps. Interop does not need cmd.exe on PATH.
Software renderer / llvmpipe
The game may run slowly. The launcher prints the adapter Bevy chose and warns when it is software; ./launcher.sh --status repeats it. Update the Windows GPU driver and verify /dev/dxg.
No audio device
Non-blocking. WSLg audio is unavailable; gameplay and networking can continue.
Dependency missing
Run ./launcher.sh --repair, then ./launcher.sh --doctor.
Tailscale unavailable
Choose safe repair. Follow its install/login prompt. Both players must be on the intended tailnet.
Host relay unreachable
Do not launch repeatedly. Confirm the host is green, the address is current, and Tailscale is connected on both machines.
Build still running
Wait. Read the displayed checklist or the reported log. Readiness never means “PID exists.”
Extended coprocessor suite
QPU/APU/IOPU/vector/physics/math/tensor/neural/crypto backends are not dependencies of this release and are not claimed as active.
