## 4. Where the two designs genuinely disagree

Three substantive disagreements, not stylistic:

**4.1 Tuned conductances vs. derived geometry.**
`OpeningDef` carries `air_conductance` and `water_conductance` as `u64`
knobs. Flow is whatever the number says. #165 derives flow from an aperture in
cm² and a head, and derives pool depth from `air_l × 10 000 / floor_cm2`, so
"the hall is ankle-deep" is a consequence of the room's size rather than a
number an author picked. This matters for the player-facing claim that water
finds the low room: with a scalar, a level author can make a puddle deep in a
cupboard and shallow in a basement, and the result is unreviewable.

**4.2 Hard-coded rule order vs. an authored, cited catalogue.**
Main's §3 ("What this model is not") and ADR-0013 both say the systems are
fixed and stylised — deliberate. #165 instead asks for a closed set of
templates and a rule record per interaction, so a level can cite which rule
produced which consequence and the adversarial review can check that every
rule a level relies on exists. Main's §5 matrix delivers the *layer* contract;
it does not deliver per-rule attribution, which is what "Level 2 needs causal
chains shown to the developer" requires.

**4.3 Capabilities and precedence.** Main has no notion of what an actor must
physically be able to do to trigger an interaction, and no precedence rule
between a manual command, an automatic trip, and a lock-out. #165 makes both
explicit. Without them, "no electrical toggle as a universal explosion
trigger" is a convention rather than a constraint.

None of these is settled by merging; all three would need main to change
something it just shipped.

## 5. Recommendation

**Split the PR. Do not merge #165 as-is, and do not close it wholesale.**

### 5.1 Now — land the CI fix on its own (2 commits, orthogonal)

`2797829` (arm 5b in `check-lock-sync.sh`) and `a875996` (8 lockfile
dependencies) have nothing to do with infrastructure design. `main` still has
**5** dependencies and still uses the same three undeclared refs
(`actions/checkout`, `actions/cache`, `actions/upload-artifact`), so the
blind spot #165 fixes is live on `main` today. Extract both commits onto a
fresh branch off `main`, open one small PR, get it green. This also has the
side benefit of un-conflicting #165, since the only conflict is in `docs/`.

Why separate: a 2-commit CI fix can be reviewed in minutes and must not wait
on a design decision, and must not be blocked by it.

### 5.2 Keep from #165 — three things, and only three

1. **`docs/architecture/infrastructure-rule-catalogue.md`** and the
   corresponding part of `infrastructure-interactions.md` — retargeted as a
   *proposal to add an authored rule layer on top of the shipped
   `scenario/infrastructure/` sim*, not as a parallel design. Justification
   §4.2, §4.3 above.
2. **The geometry encoding** (`aperture_cm2`, sill/weir crest,
   `full_depth_mm = air_l × 10 000 / floor_cm2`) as a concrete change request
   against `OpeningDef`. Justification §4.1. This is the smallest, most
   reviewable item and the one I would argue hardest for.
3. **`infrastructure-level-1.md` / `infrastructure-level-2.md`**, if and only
   if they are rewritten as *player-facing teaching levels*. Main's §11 levels
   are integration tests — they script commands and assert event sequences,
   which is a different artefact from a level a person plays. §11.1's Plant
   Room does exercise a non-destructive path (step 3: close the valve, leak
   stops), so the pedagogical claim is partly already met in prose.

Net effect: roughly 4 425 lines of docs becomes roughly 1 200, aimed at the
three questions main has not answered, against code that exists.

### 5.4 Why not the alternatives

- **Merge everything.** Reintroduces a duplicate ADR number, ships 3 000 lines
  of design that contradicts shipped code, and leaves the tick gap in place.
- **Close #165 entirely.** Loses §4.1–§4.3, which are real and cheap, and
  loses the CI fix, which is live on `main`.
- **Go all the way to `main`'s model.** Defensible — main's design is coherent
  and its `not_simulated` discipline is better than mine. But it means the
  levels cannot cite rules, and depth stays a tuned number. Worth stating as
  the fallback if the reconcile is judged not worth the review time.

- **Does anything call the infrastructure sim?** On `main` the module is

  it into `BuildingRuntime`, items 5.2.1–5.2.2 must be designed against that
  call site, not before it. This should be checked before starting the
  reconcile.
- **CI has never run on `2797829`/`a875996`** — the PR is `CONFLICTING`, and
  `pull_request` workflows do not fire. The lockfile fix is verified locally
  (`8/8 dependencies`, `7/7 used refs declared`, self-test 13/13) and by API
  read, but **not in CI**. That is a further reason to land it on a clean
  branch off `main` rather than through this PR.
